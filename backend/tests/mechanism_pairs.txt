# Second sample: 15 pairs "disease | explicit mechanism", independent of the Minikel sample (live_sample.py).
# It tests the mechanism logic — same-mechanism drugs, direction, efficacy failures vs other stop reasons, precedents —
# not a forecast. Run: python -m backend.tests.mechanism_sample   (live data; offline checks: test_mechanism_sample.py)
#
# Format: disease | mechanism | expectations (separated by ;) | what the pair tests and the history it rests on
#   query=TEXT            the parser's target query            (offline)
#   action=inhibit|activate                                      (offline)
#   approved_same>=N / approved_same=N    approved_same_moa_count (approved for this disease, same target + direction)
#   precedent=VALUE       moa_clinical_precedent
#   same+=A,B / same-=A,B                 drugs that must / must not be in the same-mechanism list
#   efficacy_failure+=A / efficacy_failure-=A   drugs that must / must not be counted as efficacy failures
#   verdict_if_confirmed!=V   the verdict once every pending LLM claim is confirmed by a human
#   verdict=A/B / verdict!=A/B   2.4: the verdict itself is (not) one of A, B. The expected verdicts are for a NEW asset
#                         with this mechanism today, with no data on its advantage: 2.5 a mechanism already approved
#                         here 2+ times is Do Not Invest (grounds "crowded"); a failed mechanism is never Invest.
# A trailing ? marks an expectation that is historically true but depends on whether public data exposes it (a stop
# reason, a registry result, a paper with an abstract): not met -> "open", not "fail".
#
# Leakage: all checks run on today's data and test what the pipeline does with it. An approval or failure that came
# after the decision date is never used here to say the system "should have known" it at that date. Dates below are
# for context only.
